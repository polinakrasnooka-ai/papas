# Формат лида (бизнес-brief)

Используй **ровно** этот формат на каждый лид. Один лид = одна площадка.
Поля не удаляй — если нет данных, пиши `не подтверждено`. Все ссылки
кликабельные, ведут на первичный источник.

Скоринг, Tier, «РЕШЕНИЕ / ПРИЧИНА / СЛЕДУЮЩЕЕ ДЕЙСТВИЕ» — **в выдачу не
печатать**. Это внутренний фильтр: лиды < 65 просто не попадают в
подборку (см. `docs/scoring.md`).

---

```markdown
**<Компания> — <Предприятие / Завод> (<Страна>)**

- **Покупатель:** <юр. название + подразделение + адрес>
- **Отрасль:** <power / steel / cement / lime / chem / glass / sugar / building materials / fillers / infrastructure> — <одна строка контекста о масштабе>
- **Что закупает:** <точное название продукта по тендеру / сайту>
- **Форма:** <open tender / framework / Dynamic Purchasing System / RFQ> на <период>, <лоты / структура>
- **Статус:** активная | планируется | закрыта | повторяющаяся
- **Дедлайн:** <дата или «регистрация открыта весь срок системы» / «не подтверждено»>
- **Объём:** <X т/год или per lot, либо «не подтверждено» + отраслевой контекст одной строкой>
- **Техтребования:** CaCO₃ <%>, фракция <мм>, стандарт <EN/ISO>; <что в SIWZ/документации>
- **Прошлые поставщики:** <компании с указанием страны и площадки>
- **Логистика:** ХОРОШАЯ | ПРИЕМЛЕМАЯ | СЛОЖНАЯ | ЭКОНОМИЧЕСКИ СОМНИТЕЛЬНАЯ — <одна фраза: расстояние, тип транспорта>
- **Допуск UA:** ДА | ВЕРОЯТНО | НЕ ПОДТВЕРЖДЕНО | НЕТ — <одна фраза с основанием>

**Ссылки:**
- Тендер: [<ID>](<URL>)[ · [<ID2>](<URL2>)]
- Подача / регистрация поставщика: [<название портала>](<URL>)
- Сайт площадки: [<домен>](<URL>)
```

---

## Правила заполнения

- **Поля не удаляй**, даже если «не подтверждено». Пустое поле читается
  как ошибка парсинга.
- **Ссылки обязательны** — минимум одна в блоке «Тендер» и одна «Подача /
  регистрация». Если тендера нет (просто мониторим покупателя), в блоке
  «Тендер» — ссылка на procurement portal или archive.
- **Техтребования — одной строкой.** Если нужно развернуть
  спецификацию (CaCO3, CaO, MgO, SiO2, фракция, влажность, реактивность) —
  это в SIWZ/документации, не в brief.
- **Прошлые поставщики — только подтверждённые имена**, никаких
  «вероятно», «по слухам».
- **Логистика — один статус + одна фраза.** Без таблицы маршрутов,
  перегрузок, пограничных переходов — это внутренний анализ, не для
  бизнес-brief.
- **Допуск UA — обязательно** и обязательно с основанием одной фразой
  (DCFTA, GPA, прямое указание в SIWZ, запрет и т.п.).
- **Решение / скоринг / next action — НЕ ПЕЧАТАТЬ.** Если
  пользователь явно просит внутренний анализ — есть отдельный флаг
  (см. раздел «Расширенный вывод» ниже).

## Что считается валидным лидом в подборке

Внутренний скоринг (см. `docs/scoring.md`): если < 65, лид **не идёт в
подборку**. Выдача пользователю содержит только лиды ≥ 65 в формате выше.

Лиды 50–64 собираются в отдельный список «на доработку» в конце выдачи,
одной строкой на лид:

```
- <Компания — Площадка (Страна)> — <чего не хватило до 65>: <одна фраза>
```

Лиды < 50 — не упоминать вообще.

## Расширенный вывод (по запросу)

Если пользователь явно просит «дай мне разбор», «покажи скоринг»,
«почему именно этот», «что ещё проверить» — печатать внутренний блок
после brief'а:

```
---
Скоринг: <X>/100 — UA допуск <X>, логистика <X>, активная закупка <X>,
contact <X>, объём <X>, спеки <X>, prev supplier/price <X>
Что нужно для участия: <документы, сертификаты, EU entity, VAT, local partner, bid bond>
Контакт procurement: <ФИО, должность, email, телефон, LinkedIn — или «не подтверждено»>
Что проверить следующим шагом: <одно конкретное действие>
```

По умолчанию — не печатать.
```
